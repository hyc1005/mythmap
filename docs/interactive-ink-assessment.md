# 开屏与宣传片“可落笔”评估

更新：2026-11-09。只做可行性评估，不改代码。

## 1. 需求复述

希望在两处展示「山海寻踪」四字的动画里，给用户一支**待准备的黑色笔触**，让用户自己落墨：

- 可操作：开屏的逐字勾绘 / 扫墨覆页阶段；宣传片对应阶段。
- 不可操作：题字重现（反白）部分；宣传片的人物形象展示部分（`神话登场` 之后）。

## 2. 现有结构

- 开屏：`frontend/src/splash/index.js` + `createInk.js` + `stage.html`，Shadow DOM 隔离；WebGL 流体画布 `#ink`，标题 SVG 在上层。
- 宣传片：`frontend/public/opening-film.html` 自包含，内嵌同一套流体代码与标题 SVG。
- 已有 API：`ink.ink(x, y, { pigment, amount, radius, dx, dy })`，坐标是画布归一化坐标；`ink.clear()`、`ink.pause()`。
- 阶段：`tick(t)` 里按 `coverStart`、`coverEnd`、`creamStart`、`repAt` 等时间点切换；`phaseEl.textContent` 已有“逐字勾绘 / 扫墨覆页 / 淡彩笔触 / 题字重现 / 落印定帧”。
- 指针事件目前只用于“点击任意处进入网站”，没有落墨交互。

## 3. 可行性结论

**技术上可行，成本中等，主要风险是 UX 与测试，不是渲染。**

- 落墨：在 `#splash-stage`（或 film 的 `stageInner`）上监听 `pointerdown/move/up`，把坐标换算成画布归一化坐标，按帧节流调用 `ink.ink()` 即可；笔触沿路径插值，避免点状断裂。
- 铅笔预览：一个跟随指针的圆点/笔尖 DOM 或 canvas 覆盖层，`pointerdown` 时才显示墨迹。
- 阶段门控：在 `tick` 中维护 `interactive = t >= writeStart && t < coverEnd`（开屏）；宣传片对应到 `神话登场` 之前。`pointerdown` 先判断阶段，非交互阶段直接忽略。
- 反白与人物段：`repAt` 之后（题字重现、落印）与 `神话登场` 之后不注册落墨，避免覆盖反白字和人物画面。
- 移动端：开屏是 `dialog` 模态，`touch-action: none` 可阻止滚动；宣传片没有滚动冲突。需要 `pointercapture`，防止手指移出画布丢事件。
- 性能：低质量流体下每帧 1–3 个 splat 可接受；限制事件频率（如 60Hz）与单次半径，避免连续拖拽把墨量打满。
- 海报/反白：不要改 `clearMode` 的渲染；只在可交互阶段追加笔触。

## 4. 需要新增的东西（评估用，不实施）

1. `stage` 上的 pointer 事件与坐标换算（含 DPR、`toCanvas` 反算）。
2. 笔触状态：`brush`（大小/透明度）、`drawing`、`lastPoint`、`lastTime`。
3. 阶段门控：把 `tick` 里的阶段判断抽成 `isInkable(t)`，两处动画共用。
4. 笔尖预览：可选；如果不做预览，用户不知道可以画。
5. 清除/复位：用户可能画满整屏；至少提供“重播”或自动随动画消散。
6. 测试：Playwright 指针手势、阶段门控、移动端不滚动、不阻塞“进入网站”按钮。

## 5. 风险

- **打断动画**：用户乱画会盖住标题；需要限制笔触大小/数量，或在标题完全出现前不开放。
- **与跳过冲突**：开屏“点击任意处进入网站”；落笔与进入需要区分（例如第一下进入笔模式，或长按落墨）。
- **移动端手势**：多点触控、双指缩放、浏览器手势；需要 `touch-action` 与 pointer 类型过滤（只接受 pen/mouse，或单指）。
- **测试与 CI**：WebGL 流体在 CI 上偶发不稳定；新增手势会扩大测试面。
- **可访问性**：纯装饰交互，不承载信息；键盘用户不应被要求落墨。
- **宣传片**：自包含单文件，改动要同步两份代码，容易漂移；最好把共用逻辑抽出来，但会动到既有构建。

## 6. 成本估计

- 开屏原型（含笔尖、门控、清除）：1–1.5 天。
- 宣传片同步：0.5 天（同一套逻辑复制/抽取）。
- 测试与两浏览器回归：0.5–1 天。
- 合计约 2–3 天；如果只做开屏原型、宣传片暂缓，约 1.5 天。

## 7. 建议

先做**开屏限定原型**，用 `?ink=1` 开关，不进入正式入口；确认三件事再决定是否铺到宣传片：

1. 用户是否知道可以画（笔尖预览与一句提示）；
2. 画完是否破坏标题/进入按钮；
3. 移动端是否误触滚动或跳过。

不建议现在改宣传片；它是自包含文件，双份维护成本高，等开屏验证后再同步。
