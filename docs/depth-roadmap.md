状态：**仅文档，未实施**。v1 起草于 2026-11-09，同日按评审意见修订为 v2；本文件不涉及代码、数据或 UI 改动。

写作原则：数字都来自当前仓库文件；引用他人建议时只保留与数据相符的部分，并单列不符之处。评审请优先核对第 1 节，再看第 4 节的取舍。

## 0. 结论摘要（修订后顺位）

1. **同名异载 + 异说校读**：只依赖现成的 `group_key` 与 `basis`，不需要人工复核标签，风险最低，可先出一个可见成果。
2. **effect / omen 语义标签**：从全文抽取、独立派生 JSON，带出处与 `basis`；可与第 1 项并行。
3. **相关条目增强**：在已有 `相关条目` 上叠加共享标签、同山与知名度权重，依赖第 2 项的标签质量。
4. **专题巡山录**：由第 2 项的标签派生候选点位，编辑只做排序与导语。

明确不做：自然语言问答 / LLM 检索、全局力导向关系图、把 45 条 `unresolved` 当欠账清理、补海经 / 大荒经、神话谱系 / 时间线。部件标签（`feature_tags` 扩充）暂缓。

## 2. 对旧建议的修正

### 2.1 45 条 `unresolved` 是文献边界，不是待办

`unresolved` 覆盖两类情况：

- 原文没有写形貌，例如“其中多蠃母”“是多怪鳥獸”“鳥獸盡白”“其中多赤鮭”；
- 本体指代不明，例如“有鳥焉其状如夸父……名曰囂”与另一处“嚣”重名。

另有大量神灵条目本来就没有固定形貌，`form_group: other` 属正常。

因此：**不得为了补齐部件标签去改写这些记录**。Sonnet 早前建议“顺手消化”它们，会把项目最谨慎的文献判断变成填充字段。

### 2.2 优先做语义枚举，而不是通用句式解析

“状如”“名曰”“其音”更像检索词；筛选价值高的是**功效**与**征兆**两类语义，用户可直接组合“西山经 + 鸟 + 见则大旱”“全山经 + 可以御火”。

### 2.3 “相关条目”已经存在，增量在权重

`DetailDrawer` 已有 `相关条目`、`同名记载`、`此地所见`、`相关章节`，`related_entry_ids` 覆盖 367/384。增量是：共享标签、同山、共享征兆的权重，以及按 `bestiary-notability.json` 排序。

### 2.4 evidence 不够，抽取要回到全文

v1 曾写“evidence 与 quote 已含所需语句”，这一点被评审推翻并经复核确认：evidence 中位仅 17 字。准确表述是：**数据无需新增采集，但抽取必须以 `quote` / `commentary_quote` / `description` 全文为输入，evidence 只作交叉核对**。

## 3. 两处容易搞错的数据事实

### 3.1 肥遺 与 肥𧔥 不是同名

- 英山与浑夕的“肥遺”共用 `group_key = 肥遺`，可以并排；
- 太华山的“肥𧔥”是另一个字、另一个组，**不进入同名视图**。

### 3.2 “帝之二女”四条不是同一组

洞庭段有 4 条相关记录：正文属 `group_key = 帝之二女`（且 `review_status` 为 `unresolved`）；尧女说、舜妃说、湘君湘夫人均为 `basis: comparison`。

因此需要两个视图：

- **同名异载**：同 `group_key`、≥2 条；
- **异说校读**：正文 + `basis: comparison` 条目。

## 4. 四个顺位

### 4.1 同名异载 + 异说校读（第一顺位）

目标：同 `group_key` 的 2–5 条记录并排；`basis: comparison` 的条目单列“异说”视图。

数据前置：`group_key`、`basis`、`book_key`、`classification.evidence` 均为现成字段，不需要人工复核标签。

风险：把 comparison 误当同名（见 3.2）；手机端需降级为上下排列；`帝之二女` 正文本身是 `unresolved`，并排时不能声称已解决形貌。

验收：

- 同名视图只在 `group_key` 内启用，条目数与数据一致（如兕 5、㸲牛 5、羬羊 4）；
- 异说视图只收录 `basis: comparison`；
- 高亮篇目、形貌与原文差异，但不改写原文；
- 键盘与 Esc 行为符合现有抽屉规范。

估计：3–4 天。

### 4.2 effect / omen 语义标签（第二顺位，可与 4.1 并行）

目标：把全文中的功效与征兆提炼成可筛选枚举，沿用现有筛选摘要 UI。

数据前置：必须回 `quote` / `commentary_quote` / `description` 全文抽取；`evidence` 仅用于交叉核对。预计可覆盖约 131/384 条（约 34%），其余条目保持无标签。

初版枚举（按实际数据取舍）：

- `effect_tags`：`ward_fire`（御火/辟火）、`ward_war`（御兵）、`ward_evil`（不蛊/御凶）、`cure_disease`（已癘/已痔/已疣）、`travel`（善走/不迷）、`calm`（不畏/不惑/已忧）、`nourish`（不饥）。备注：`多力` 在现有全文里为 0 条，暂不设 `strength`。
- `omen_tags`：`flood`、`drought`、`war`、`famine`、`plague`、`fire`、`wind`，另加 **`bountiful`（大穰/其国大穰）**、**`peace`（安宁）** 与 **`other_omen`（土功/放士/大繇等政务人事）**，避免“灾异”叙事盖过原文的吉兆与政务记录。

存放位置：**独立派生 JSON**（按条目 id 索引，每个标签附 `basis` 与出处引文），不并入 `bestiary-metadata.json`、也不并入 `feature_tags`。理由：`feature_tags` 描述形体，effect/omen 描述原文声称的功效，语义与复核标准不同；写进 metadata 还会影响素材清单与审计计数。

风险：

- 词义歧义（“御火”是防火还是召火），必须人工复核并保留 `basis`；
- 覆盖率约三分之一，需在 UI 上说明“仅收录原文明确记载者”；
- 标签命名空间与 `feature_tags` 要一次定清楚。

验收：

- 每个标签可在异兽谱筛选器中单独选中并正确计数；
- 标签可点击回筛，详情页不改变原文；
- `verify-bestiary` 增加标签断言；
- gzip 增量实测并记录（预算 25 KiB）。

估计：3–5 天（含人工复核）。

### 4.3 相关条目增强（第三顺位）

目标：在现有 `相关条目` 上叠加共享标签、同山、共享征兆的相似度，并按知名度排序。

数据前置：`related_entry_ids`、`context_place_id`、`feature_tags`，以及 4.2 的 effect/omen 标签。

风险：标签质量依赖 4.2；同山条目过多时需截断（建议前 4 条）。

验收：

- 排序优先级：共享标签数 → 同山 → 知名度；
- 390px 宽抽屉不横向溢出；
- 不新增依赖，不改变已有焦点与返回逻辑。

估计：2–3 天。

### 4.4 专题巡山录（第四顺位）

目标：3–4 条主题导览，每条 6–8 个点位，复用现有导览与故事播放。

数据前置：现有点位、章节、故事数据；**点位由 4.2 的标签生成候选**（例如 `omen_flood` + `omen_drought` + `omen_war`），编辑只做排序、导语与依据核对。每个点位须附文献依据；标签自带出处后，这一步成本很低。

候选主题：

- 灾异志·水旱兵疫（毕方、肥遺、长右、朱厌、蜚）；
- 山海方伎·服食辟邪（九尾狐、猼訑、䍺、青耕）；
- 神灵形貌·五山祭礼（六段祭礼总括）。

风险：编辑成本高于工程成本；与现有“开始游历”并存时要避免状态冲突。

验收：

- 路线可进入、退出、切换语言；
- 不新增全局状态，复用现有播放组件；
- 每个点位都能回到原文与地图，并显示文献依据。

估计：2–3 天工程 + 编辑投入。

## 5. 明确不做

- **自然语言问答 / LLM 检索**：与现有搜索和结构化筛选重叠，且有编造原文风险。
- **全局力导向关系图**：犀、兕、熊、罴这类高频普通动物会把图连成废网，也与纸本版画美学和体积预算冲突。
- **清理 45 条 `unresolved`**：文献边界，不是技术债。
- **补海经 / 大荒经**：内容扩张而非深度，且与 README 已声明的阅读范围冲突。
- **神话谱系 / 时间线**：与“不过度演绎”的原则冲突。
- **部件标签（`feature_tags` 扩充）暂缓**：现有 10 类在 evidence 范围内自洽，问题在覆盖面而不是漏标；扩标签的收益低于 effect/omen。
