# 探索深度路线（评审稿 v5）

状态：**评审稿 + 首版实现**。v1 起草于 2026-11-09，同日经三轮评审修订至 v4；v5 记录 4.1 与 4.2 数据层的落地情况。

数字均来自当前仓库文件。第 6 节列出已定事项与仍需用户决定的少数问题。

## 0. 结论摘要

1. **同名异载 + 异说校读**：只依赖现成的 `group_key` 与 `basis`，不需要人工复核标签，风险最低。
2. **effect / omen 语义标签**：从全文抽取、独立派生 JSON，带出处与 `basis`；可与第 1 项并行。
3. **相关条目增强**：在已有 `相关条目` 上叠加共享标签、同山与知名度权重，依赖第 2 项的标签质量。
4. **专题巡山录**：先做 2–3 条，入口独立；点位由第 2 项的标签派生候选，编辑只做排序、导语与依据核对。

明确不做：自然语言问答 / LLM 检索、全局力导向关系图、把 45 条 `unresolved` 当欠账清理、补海经 / 大荒经、神话谱系 / 时间线。部件标签（`feature_tags` 扩充）暂缓。

## 2. 三处需要纠正的理解

### 2.1 45 条 `unresolved` 是文献边界，不是待办

`unresolved` 覆盖两类情况：

- 原文没有写形貌，例如“其中多蠃母”“是多怪鳥獸”“鳥獸盡白”“其中多赤鮭”；
- 本体指代不明，例如“有鳥焉其状如夸父……名曰囂”与另一处“嚣”重名。

另有大量神灵条目本来就没有固定形貌，`form_group: other` 属正常。**不得为了补齐标签去改写这些记录。**

### 2.2 优先做语义枚举，而不是通用句式解析

“状如”“名曰”“其音”更像检索词；筛选价值高的是功效与征兆两类语义。

### 2.3 “相关条目”已经存在，增量在权重

`DetailDrawer` 已有 `相关条目`、`同名记载`、`此地所见`、`相关章节`，`related_entry_ids` 覆盖 367/384。增量是共享标签、同山、共享征兆的权重，以及按 `bestiary-notability.json` 排序。

### 2.4 回全文是为了拿到完整出处句，不是为了扩大覆盖

仅看 `evidence` 已能命中 126 条，回全文 128 条，差距只有个位数。回全文的真正理由是：`evidence` 中位仅 17 字，常在“其状如×”处截断，**作筛选标签的出处引文不完整**。抽取规则应以 `quote` / `commentary_quote` / `description` 为输入，`evidence` 只做交叉核对。

因此，覆盖率约三分之一是**原文本身的上限**——大部分条目原文没有写功效或征兆，全量人工标注也不会明显提高这个数字。

## 3. 两处容易搞错的数据事实

### 3.1 肥遺 与 肥𧔥 不是同名

- 英山与浑夕的“肥遺”共用 `group_key = 肥遺`，可以并排；
- 太华山的“肥𧔥”是另一个字、另一个组，**不进入同名视图**。

### 3.2 “帝之二女”四条不是同一组

洞庭段 4 条相关记录中，只有正文属 `group_key = 帝之二女`（且 `review_status` 为 `unresolved`）；尧女说、舜妃说、湘君湘夫人均为 `basis: comparison`。

因此需要两个视图：**同名异载**（同 `group_key`、≥2 条）与 **异说校读**（正文 + `basis: comparison`）。

### 3.3 同名组会跨出山经五部

`bestiary-metadata.json` 有 5 条不属五部山经：大荒北经 2、海内北经 1、海外北经 1、海内西经 1。穷奇的同名组就是西山经 + 海内北经。

这与“阅读段只覆盖五部山经”不冲突：这 5 条是有意保留的交叉引用。同名视图必须在 UI 上标出篇名，避免读者误以为都在阅读范围内。

## 4. 四个顺位

### 4.1 同名异载 + 异说校读（第一顺位）

目标：同 `group_key` 的 2–5 条记录并排；`basis: comparison` 的条目单列“异说”视图。

数据前置：`group_key`、`basis`、`book_key`、`classification.evidence` 均为现成字段。

风险：把 comparison 误当同名（见 3.2）；泛称组信息量低（见验收）；手机端需降级为上下排列；`帝之二女` 正文本身是 `unresolved`，并排时不能声称已解决形貌。

验收样例（选有实质差异的组）：

- 穷奇：西山经“状如牛蝟毛” vs 海内北经“状如虎有翼”；
- 羬羊：4 条，篇目与形貌存在差异；
- 朱厌：2 条；
- 肥遗：英山（鸟，食之已癘、可以殺蟲）vs 浑夕（蛇，见则其国大旱）；
- 旋龟：2 条。

泛称组（兕 5、㸲牛 5、犀 4、马 3、旄牛 3 等，原文多为“其兽多犀兕”式罗列）应：按 `bestiary-notability.json` 降权，或标注“泛称”后默认折叠，不作为并排样例。

验收：

- 同名视图只在 `group_key` 内启用，条目数与数据一致；
- 异说视图只收录 `basis: comparison`；
- 每侧显示 `book_key`（含 3.3 的 5 条跨部条目）；
- 高亮篇目、形貌与原文差异，但不改写原文；
- 键盘与 Esc 行为符合现有抽屉规范。

**实现状态（2026-11-09）**：首版已落地。`DetailDrawer` 增加「并列校读」开关与差异高亮，`bestiary.js` 增加 `comparisonEntries`，「异说校读」区块列出 `basis: comparison` 条目；泛称组显示提示但未做折叠/降权；`verify-bestiary` 已覆盖穷奇并列与帝之二女异说。

估计：3–4 天。

### 4.2 effect / omen 语义标签（第二顺位，可与 4.1 并行）

目标：把全文中的功效与征兆提炼成可筛选枚举，沿用现有筛选摘要 UI。

数据前置：以全文（`quote` / `commentary_quote` / `description`）为输入，`evidence` 仅交叉核对；预计覆盖约 128/384 条（约三分之一），其余保持无标签。

**抽取前必须做字形归一**：数据繁简与异体混用，规则里写“御火”会漏掉绝大多数（实测 `禦火` 7、`御火` 2；`禦兵` 4、`御兵` 0；`禦疫` 1、`御疫` 0；`見則` 50、`见则` 9）。归一表至少覆盖 禦/御、見/见、靣/面、訛/讹 等，并把归一表与版本记录在案。

**句式要区分语义**：

- `可以已×` / `可以禦×` / `可以御×` 是功效；
- `可以为×`（如旋龟“可以为底”）是用途，不进功效标签，单列 `usage` 或不收录；
- “其脂可以已腊”这类部件用途，同样按用途处理。

初版枚举（按实际数据取舍）：

- `effect_tags`：`ward_fire`（禦火/御火/辟火）、`ward_war`（禦兵）、`ward_evil`（不蠱/禦凶/殺蟲）、`ward_plague`（禦疫）、`cure_disease`（已癘/已痔/已疣）、`travel`（善走）、`calm`（不畏/不惑/不眯/已忧）、`nourish`（不飢）。`多力` 全文为 0 条，不设 `strength`。
- `omen_tags`：`flood`、`drought`、`war`、`famine`、`plague`、`fire`（訛火）、`wind`，另加 **`bountiful`（大穰）**、**`peace`（安宁）** 与 **`other_omen`（土功/放士/大繇等政务人事）**。

存放位置：**独立派生 JSON**（按条目 id 索引，每个标签附 `basis` 与出处引文），不并入 `bestiary-metadata.json`、也不并入 `feature_tags`。理由：`feature_tags` 描述形体，effect/omen 描述原文声称的功效；写进 metadata 还会影响素材清单与审计计数。

风险：

- 词义歧义（“禦火”是防火还是召火），必须人工复核并保留 `basis`；
- 覆盖率约三分之一，UI 需说明“仅收录原文明确记载者”；
- 标签命名空间与 `feature_tags` 要一次定清楚。

验收：

- 每个标签可在异兽谱筛选器中单独选中并正确计数；
- 标签可点击回筛，详情页不改变原文；
- `verify-bestiary` 增加标签断言；
- gzip 增量实测并记录（预算 25 KiB）。

**实现状态（2026-11-09）**：数据层已完成。`data/build_semantic_tags.py` 产出 `frontend/src/bestiary-semantic-tags.json`：95 条（effect 41、omen 54），每条带 `match`、`evidence`、`source` 与 `basis`；按字段分别抽取，避免把郭注粘进原文；`可以為×` 不计入。尚未接入筛选 UI，标签仍标 `status: auto`，待人工复核。

估计：3–5 天（含人工复核）。

### 4.3 相关条目增强（第三顺位）

目标：在现有 `相关条目` 上叠加共享标签、同山、共享征兆的相似度，并按知名度排序。

数据前置：`related_entry_ids`、`context_place_id`、`feature_tags`，以及 4.2 的标签。

风险：标签质量依赖 4.2；同山条目过多时截断（建议前 4 条）。

验收：

- 排序优先级：共享标签数 → 同山 → 知名度；
- 390px 宽抽屉不横向溢出；
- 不新增依赖，不改变已有焦点与返回逻辑。

估计：2–3 天。

### 4.4 专题巡山录（第四顺位）

目标：先做 **2–3 条**主题导览，每条 6–8 个点位；点位由 4.2 的标签生成候选，编辑只做排序、导语与依据核对，每个点位附文献依据。**入口独立，不复用现有“开始游历”入口与状态机**。

候选主题（已按原文校正）：

- **见则志**（含灾异与吉兆）：`omen_drought` 浑夕肥遗（`beast-beishan-feiyi-hunxi`，蛇）、`omen_war` 朱厌、`omen_flood` 长右、`omen_plague` 蜚、`omen_fire` 毕方（訛火）、`omen_bountiful` 文鳐鱼、`omen_peace` 当康。
- **服佩辟邪**：九尾狐（食者不蛊）、猼訑（佩之不畏）、青耕（可以禦疫）、英山肥遗（`beast-xishan-feiyi-ying`，食之已癘、可以殺蟲）。**䍺 不入此主题**：原文“无口，不可杀也”，没有服食功效。
- **神灵形貌·五山祭礼**：六段祭礼总括。

风险：编辑成本高于工程成本；独立入口降低与“开始游历”的状态冲突，但要确认播放组件可被两条路径复用而不互相打断；同名条目必须写 id，不能只写名字（见 3.1）。

验收：

- 独立入口可进入、退出、切换语言；
- 不与“开始游历”共享或接管其状态机；
- 可复用现有播放组件，但不改变其对外状态语义；
- 每个点位都能回到原文与地图，并显示文献依据与篇名。

估计：2–3 条路线约 2 天工程 + 编辑投入；后续每增一条主要增加编辑成本。

## 5. 明确不做

- **自然语言问答 / LLM 检索**：与现有搜索和结构化筛选重叠，且有编造原文风险。
- **全局力导向关系图**：犀、兕、熊、罴这类高频普通动物会把图连成废网，也与纸本版画美学和体积预算冲突。
- **清理 45 条 `unresolved`**：文献边界，不是技术债。
- **补海经 / 大荒经**：内容扩张而非深度，且与 README 已声明的阅读范围冲突。
- **神话谱系 / 时间线**：与“不过度演绎”的原则冲突。
- **部件标签（`feature_tags` 扩充）暂缓**：现有 10 类在 evidence 范围内自洽，问题在覆盖面而不是漏标；收益低于 effect/omen。

## 6. 已定事项与下一步

已定：

- 标签存放：独立派生 JSON，带 `basis` 与出处引文。
- 覆盖率：约三分之一是原文上限，不做全量人工标注去追覆盖面。
- 专题点位：逐点附文献依据与篇名。
- 同名视图：必须显示 `book_key`，并覆盖 3.3 的 5 条跨部条目。
- **effect/omen 初版枚举按本文件 v3 定稿**，`ward_evil` 吸收 `殺蟲`（`ward_fire`、`ward_war`、`ward_evil`、`ward_plague`、`cure_disease`、`travel`、`calm`、`nourish`；`omen` 为 `flood`、`drought`、`war`、`famine`、`plague`、`fire`、`wind`、`bountiful`、`peace`、`other_omen`）。
- **专题巡山录先做 2–3 条，入口独立，不复用“开始游历”入口与状态机**。

下一步：4.1 首版与 4.2 数据层已完成；剩余工作是把 effect/omen 标签接入筛选 UI、完成人工复核，以及 4.3 相关条目增强与 4.4 专题巡山录。
