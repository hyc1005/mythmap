# 探索深度路线（评审稿）

状态：**仅文档，未实施**。起草于 2026-11-09，用于交付另一位评审 agent 核对；本文件不涉及代码、数据或 UI 改动。

写作原则：所有数字都来自当前仓库文件；凡引用他人建议，只保留与数据相符的部分，并单列不符之处。评审时请优先核对第 1、2 节的事实，再看第 4 节的取舍是否成立。

## 0. 结论摘要

四个顺位，按“数据现成度 × 用户价值 × 风险”排序：

1. **effect / omen 语义标签**（离线枚举，复用现有筛选器）。
2. **相关条目增强**（在已有 `相关条目` 上叠加共享标签、同山与知名度权重）。
3. **同名异载 + 异说校读**（只对 `group_key` 同名组与 `basis: comparison` 条目）。
4. **专题巡山录**（纯数据配置，复用导览与故事播放）。

明确不做：自然语言问答 / LLM 检索、全局力导向关系图、把 45 条 `unresolved` 当欠账清理、补海经、神话谱系/时间线。

## 2. 对既有建议的三处修正

### 2.1 45 条 `unresolved` 是文献边界，不是待办

`unresolved` 覆盖两类情况：

- 原文没有写形貌，例如“其中多蠃母”“是多怪鳥獸”“鳥獸盡白”“其中多赤鮭”；
- 本体指代不明，例如“有鳥焉其状如夸父……名曰囂”与另一处“嚣”重名，无法断定是同一物。

另有大量神灵条目（黄帝、白帝少昊、蓐收、江疑、帝之二女等）本来就没有固定形貌，`form_group: other` 属正常。

因此：**不得为了补齐部件标签去改写这些记录**。Sonnet 建议“顺手消化”它们，会把项目最谨慎的文献判断变成填充字段。

### 2.2 优先做语义枚举，而不是通用句式解析

“状如”“名曰”“其音”这类句式抽取更像检索词扩充，筛选价值低；真正能复用的是**功效**与**征兆**两类语义：用户可以直接组合“西山经 + 鸟 + 见则大旱”“全山经 + 可以御火”。

数据基础够用，但有两条限制：

- `動則` 仅 1 条，相关规则应删除；
- 标签必须在入库前人工复核，并保留 `basis`（正文 / 郭注 / 比较），否则会把郭注里的“御火”当成经文依据。

### 2.3 “相关条目”已经存在，增量在权重而不是区块

`DetailDrawer` 已有 `相关条目`、`同名记载`、`此地所见`、`相关章节`，`related_entry_ids` 覆盖 367/384。Grok 所说的“关系图谱”在本仓库不需要从零建图，增量工作是：

- 给现有相关条目加共享标签、同山、共享征兆的权重；
- 用 `bestiary-notability.json` 排序，避免把“多犀兕”这类泛称顶到前面。

## 3. 两处容易搞错的数据事实

### 3.1 肥遺 与 肥𧔥 不是同名

- 英山与浑夕的“肥遺”共用 `group_key = 肥遺`，可以并排；
- 太华山的“肥𧔥”是另一个字、另一个组，**不进入同名视图**。

### 3.2 “帝之二女”四条不是同一组

洞庭段有 4 条相关记录，但只有正文属 `group_key = 帝之二女`；尧女说、舜妃说、湘君湘夫人均为 `basis: comparison`，是校勘材料，不是同名异载。

因此需要两个不同视图：

- **同名异载**：同 `group_key`，≥2 条，例如穷奇、羬羊、羬羊 4 条；
- **异说校读**：正文 + `basis: comparison` 条目，例如帝之二女、启母、湘君湘夫人。

## 4. 四个顺位

### 4.1 effect / omen 语义标签（第一顺位）

目标：把“食之/佩之/服之/可以/见则”里的功效与征兆提炼成可筛选枚举，沿用现有筛选摘要 UI。

数据前置：`classification.evidence` 与 `quote` 已含所需语句，无需新增采集。

范围（建议初版）：

- `effect_tags`：`ward_fire`（御火/辟火）、`ward_war`（御兵）、`ward_evil`（不蛊/御凶）、`cure_disease`（已癘/已痔/已疣）、`travel`（善走/不迷）、`calm`（不畏/不惑/已忧）。
- `omen_tags`：`flood`、`drought`、`war`、`famine`、`plague`、`fire`、`wind`。

风险：

- 词义歧义（“御火”是防火还是召火），必须人工复核并保留 `basis`；
- 覆盖不均，预计只有 60–90 条能落标签；
- 标签命名空间与 `feature_tags` 的关系要一次定清楚（合并还是并列）。

验收：

- 每个标签都能在异兽谱筛选器中单独选中并正确计数；
- 标签可点击回筛，详情页不改变原文；
- `verify-bestiary` 增加标签断言；
- gzip 增量实测记录在案（预算 25 KiB）。

估计：3–5 天（含人工复核）。

### 4.2 相关条目增强（第二顺位）

目标：在现有 `相关条目` 上叠加共享标签、同山、共享征兆的相似度，并按知名度排序。

数据前置：`related_entry_ids`、`context_place_id`、`feature_tags`（4.1 完成后含 effect/omen）。

风险：标签质量依赖 4.1；同山条目过多时需要截断（建议前 4 条）。

验收：

- 相关条目按“共享标签数 → 同山 → 知名度”排序；
- 390px 宽抽屉不横向溢出；
- 不新增依赖，不改变已有焦点与返回逻辑。

估计：2–3 天。

### 4.3 同名异载 + 异说校读（第三顺位）

目标：同 `group_key` 的 2–5 条记录并排；`basis: comparison` 的条目单列“异说”视图。

数据前置：`group_key`、`basis`、`book_key`、`classification.evidence`。

风险：把 comparison 误当同名（见 3.2）；并排布局在手机端需要降级为上下排列。

验收：

- 同名视图只在 `group_key` 内启用，条目数与数据一致；
- 异说视图只收录 `basis: comparison`；
- 高亮差异（篇目、形貌、原文）但不改写原文；
- 键盘与 Esc 行为符合现有抽屉规范。

估计：3–4 天。

### 4.4 专题巡山录（第四顺位）

目标：3–4 条主题导览，每条 6–8 个点位，复用现有导览与故事播放。

数据前置：现有点位、章节、故事数据；需要编辑撰写导语与顺序。

候选主题：

- 灾异志·水旱兵疫（毕方、肥遺、长右、朱厌、蜚）；
- 山海方伎·服食辟邪（九尾狐、猼訑、䍺、青耕）；
- 神灵形貌·五山祭礼（六段祭礼总括）。

风险：编辑成本高于工程成本；导览状态机与现有“开始游历”并存时要避免状态冲突。

验收：

- 路线可进入、可退出、可切换语言；
- 不新增全局状态，复用现有播放组件；
- 每个点位都能回到原文与地图。

估计：2–3 天工程 + 编辑投入。

## 5. 明确不做

- **自然语言问答 / LLM 检索**：与现有搜索和结构化筛选重叠，且有编造原文风险。
- **全局力导向关系图**：犀、兕、熊、罴这类高频普通动物会把图连成废网，也与纸本版画美学和体积预算冲突。
- **清理 45 条 `unresolved`**：文献边界，不是技术债。
- **补海经 / 大荒经**：内容扩张而非深度，且与 README 已声明的阅读范围冲突。
- **神话谱系 / 时间线**：与“不过度演绎”的原则冲突。
